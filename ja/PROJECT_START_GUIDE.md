# プロジェクト開始手順書

## 1. 目的

この手順書は、AIと協力して新しいソフトウェア開発を始める際の標準的な進め方を定めるものです。

プロジェクトごとに開発の進め方が大きく変わらないようにし、計画、実装、テスト、GitHubによる変更管理を一貫した手順で進めます。

共通の開発ルールについては、`AI_DEVELOPMENT_MANUAL.md` を参照してください。

## 2. 使用するファイル

新しいプロジェクトを始める際は、次のファイルを使用します。

- `ja/AI_DEVELOPMENT_MANUAL.md`：AIと協力して開発する際の共通ルール
- `templates/PROJECT_START_PROMPT.md`：AIにプロジェクトの開始を指示するためのテンプレート

英語で開発を進める場合は、次のファイルを使用します。

- `en/AI_DEVELOPMENT_MANUAL.md`
- `templates/PROJECT_START_PROMPT.en.md`

プロジェクト開始テンプレートは、対象プロジェクトの情報に合わせて必要な項目を記入して使用します。

## 3. 開発開始前の準備

新しいプロジェクトを始める前に、次の項目を整理します。

- プロジェクト名
- 作成したいものとその目的
- 想定する利用者
- 必要な機能
- 使用したい技術や開発環境
- デザインや操作性の希望
- 制約や注意事項
- 現在の進捗
- 今回取り組みたい作業

まだ決まっていない項目は、無理に埋める必要はありません。AIに相談しながら決定します。

## 4. AIへの指示

1. 開発マニュアルとプロジェクト開始テンプレートをAIに渡します。
2. テンプレートにプロジェクト固有の情報を記入します。
3. 既存のコードやファイルがある場合は、関連するファイルも確認できるようにします。
4. AIに現在の状況、要件、制約を整理させます。
5. 最初に取り組む作業と、その理由を提案させます。
6. 内容を確認し、合意してから実装を始めます。

情報が不足している場合は、AIに必要な質問をさせます。重要な前提を確認せずに実装を進めないようにします。

## 5. 実装の進め方

開発は、確認しやすい小さな工程に分けて進めます。

各工程では、原則として次の順序を守ります。

1. 今回の目的と完了条件を確認する。
2. 変更対象のファイルと変更理由を確認する。
3. 実装する。
4. 実行やテストによって動作を確認する。
5. 結果と残っている課題を整理する。
6. 次の工程に進む前に内容を確認する。

一度に多くの変更を加えることは避け、問題が発生した際に原因を特定しやすい状態を保ちます。

既存の機能やデザインに影響する場合は、変更前にその影響を確認します。

## 6. テストと確認

変更した内容に応じて、適切な方法で動作を確認します。

- 実装した機能が期待どおりに動作するか
- 既存の機能に問題が発生していないか
- エラーや警告が発生していないか
- 必要な画面や操作が正しく動作するか

実行していないテストを、実施済みとして報告してはいけません。

確認できた事実、未確認の事項、推測を区別して報告します。

## 7. GitHub Desktopによる変更管理

GitHub Desktopを使用して変更を管理します。

1. 作業開始前に、現在のブランチと同期状態を確認します。
2. 変更したファイルと差分を確認します。
3. 意味のある作業単位でコミットします。
4. コミットメッセージには変更内容を簡潔に記載します。
5. 動作確認後、適切なタイミングでPushします。
6. Push後、GitHub上に変更が反映されていることを確認します。

コミットやPushの前には、不要な変更や機密情報が含まれていないか確認します。

APIキー、パスワード、アクセストークンなどの秘密情報をリポジトリに登録してはいけません。

削除や上書きなど、元に戻すことが難しい操作を行う場合は、実行前に影響を確認します。

## 8. 作業完了時の報告

各工程が完了したら、次の内容を整理します。

- 完了した作業
- 変更したファイル
- 実施したテストとその結果
- 未解決の問題や注意点
- 次に推奨する作業
- コミット・Pushを行うべきタイミング

ユーザーによる確認が必要な工程では、結果を説明し、確認を得てから次に進みます。

## 9. プロジェクトの継続

次の作業を始める際は、前回の進捗、変更内容、残っている課題を確認します。

必要に応じて、関連ファイルやGitHub上の最新の変更を確認し、現状と異なる前提で作業しないようにします。

作業の継続に必要な情報が不足している場合は、推測で補わず、確認してから進めます。

## 10. 基本方針

- 小さな工程に分けて進める。
- 実装前に目的と変更内容を確認する。
- 既存の機能や設計を尊重する。
- テスト結果を事実に基づいて報告する。
- GitHubで変更履歴を管理する。
- 不明点を放置せず、必要に応じて質問する。
- 各工程の完了を確認してから次に進む。
